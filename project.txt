
# UNIQUE PROPERTY & CONSTRUCTION COMPANY — WEBSITE DEVELOPMENT

## 1. Project Overview

Build a professional, modern, responsive website for **Unique Property & Construction Company**, a business operating in building construction and real estate management.

The company offers:
- Residential construction
- Commercial construction
- Property management
- Property sales
- Property rentals

The company's existing tagline is:

**“If you can dream it, we can build it.”**

The website should establish credibility, communicate the company's services clearly, attract potential clients, and make it easy for visitors to enquire about construction projects or real estate opportunities.

The website must feel like a credible construction and real estate business, not a generic business template.

---

# 2. Recommended Technology Stack

**The following stack is the project's technical standard. Use it throughout development unless a change is justified and approved by the project owner.**

### Frontend
- HTML5 — semantic page structure.
- Tailwind CSS v4 — styling and responsive layouts.
- Vanilla JavaScript — interactivity and frontend behaviour.
- Django Templates — rendering dynamic pages from the backend.

### Backend
- Python — primary backend language.
- Django — web framework, routing, business logic, forms and administration.

### Database
- PostgreSQL — primary relational database.

### Development and version control
- Visual Studio Code — development environment.
- Python virtual environment — dependency isolation.
- Git — version control.
- GitHub — source-code repository.
- Node.js and npm — Tailwind CSS v4 build tooling where required.

### Design and visual resources
- Figma — interface planning and design exploration.
- Lucide Icons — interface icons.
- Google Fonts — typography, or locally hosted alternatives where appropriate.
- Properly licensed architectural and real estate imagery where original company photographs are unavailable.

### Testing and quality assurance
- Chrome DevTools — browser inspection and debugging.
- Lighthouse — performance, accessibility and SEO audits.
- Django testing tools — backend and application tests.
- Playwright — optional browser automation if required.

### SEO and analytics
- Google Search Console — search performance monitoring.
- Google Analytics 4 — optional visitor analytics, subject to project-owner approval and appropriate privacy implementation.

### Deployment
Use a hosting provider that supports:
- Python and Django applications.
- PostgreSQL.
- Environment variables and secure production configuration.
- Static asset serving.
- HTTPS and custom domain configuration.
- Reliable application deployment and backups.

**Do not select a hosting provider, purchase a domain, or incur paid service costs without approval.**

### Technology restrictions

Unless the project owner approves a documented change:

- Do not use React.
- Do not use Next.js.
- Do not use Vue.
- Do not replace Django with Node.js or another backend framework.
- Do not introduce unnecessary libraries or services.
- Do not use a separate frontend application when Django Templates can achieve the requirement.

Tailwind CSS v4 must be implemented using its current conventions. Do not mix Tailwind v3 configuration instructions into the project.

The goal is a straightforward, maintainable Django application with a clean frontend, not an unnecessarily complicated architecture.

---

# 3. Global Development Instructions

Apply these instructions throughout every phase:

1. Inspect the existing project structure before making changes.
2. Preserve existing working code unless there is a clear reason to modify it.
3. Follow the specified technology stack.
4. Do not invent company information, achievements, testimonials, certifications, project history or property listings.
5. Clearly identify information that still needs confirmation from the business owner.
6. Avoid unnecessary complexity, dependencies and overengineering.
7. Every button, link, form and interactive element must have a defined function.
8. Make the website responsive across mobile, tablet and desktop.
9. Prioritise accessibility, performance, security and maintainability.
10. Keep code organised and reusable.
11. Explain important implementation decisions.
12. Update `TODO.md` and `project_status.md` after completing each major phase.
13. Do not claim that a feature has been tested or completed unless it has actually been tested.
14. Do not deploy, purchase services or publish the website without explicit approval.
